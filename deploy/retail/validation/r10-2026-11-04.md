# 自然月预算续窗验收

日期：2026-11-04

状态：本地双 worker 已启用，生产未改动。完整实现提交、分组结果和部署状态见 [R10 记录](r10-2026-11-04.json)

## 功能与操作

全站可写管理员从 Customer Wallets 的账号行打开 Model budgets，再选 Monthly plans。New monthly plan 选择精确公开模型、UTC 或 Asia/Shanghai、下一个或更晚的完整月份及 USD 额度。客户在个人 Wallet 查看自己的窗口和月度计划，没有新建、调额或停止入口

Change future limit 只修改未来完整月份。当前已开始窗口及其消费、预扣、配置和请求 allocation 保留；停止已开始计划只在月底生效，尚未开始的计划可以明确取消。取消的窗口仍保留记录，标为 Cancelled by monthly plan，不能再通过手动窗口编辑或安排后继

续期 worker 只创建当前和下一月份，停机后不补造已经结束的月份。缺少应有窗口时拒绝请求，关闭入口或 worker 也不变成无限额。两 Key、不同资源池和同一公开模型共用账号额度；模型权限、钱包余额和其他限流仍分别检查

## 真实原生网关

隔离 PostgreSQL 仅复制表结构，源数据复制为零；两个 worker、独立 Redis、本地固定 OpenAI 兼容上游运行真实鉴权、预扣和结算，没有外部模型费用

实际创建、同键重放、冲突重放和陈旧版本验证通过。普通用户访问全站管理路径由原生门禁提前返回 401，只读管理员写入 403；本人计划投影只有安全额度字段，跨账号 404，未知查询 422 且不回显输入。控制面响应 private/no-store，推理错误不套用这一管理接口专用头部断言

明确停止两个续窗 worker 后，只在新合成定义中插入过去首次月份，不改已有身份或系统时钟。当前窗口缺失时，两 Key 均 429、上游调用零、钱包与账本不变。重启两个原生 worker 后，只产生当前和下一月两个唯一完整窗口，不补已结束历史月份

两 Key、两资源池实际完成两条请求，合计精确结算 28,000 nanos，共用同一冻结 policy。第三请求 429，未到上游，钱包和预算预扣归零。修改未来额度及停止计划后，本月窗口、金额、消费和配置保持原样，本月限制继续生效，下一窗口取消

## 浏览器与隐私

实际管理员页面把合成额度改为 $2.123456789，确认停止后，重新为同模型创建 $3.000000001 的未来计划。只读数据库复核精确整数、旧窗口 disabled、新窗口 enabled，账号没有 charge、reservation 或 allocation，审计顺序为 created、updated、stopped、created

普通客户只有自己的只读计划与窗口，没有管理 Actions；真实 viewer 访问 Customer Wallets 显示 Access required。最终构建的取消窗口标签已实际核验，旧手动窗口的暂停语义保留。所有验收登录均退出，临时浏览器页关闭

工作区 outputs 保存 r10-monthly-created-and-stopped、r10-monthly-customer、r10-monthly-viewer-denied 和 r10-cancelled-window 截图，均为合成账号，未另外进行移动端或整个后台视觉验收

R10 在原生审计桥投递前和投递后扫描完整行 JSON：SpendLogs 4 行、请求 trace 10 行、操作事件 11/12 行、原生 outbox 1/0 行，本批静态 provider、密码、session 与 Key 的明文 marker 命中零，运行日志同样为零。身份/Key 权威表和配置表不在该扫描范围；这不补造 R9 托管 Vault 值的数据库验证结论

## 对请求链路的有限对照

R9 基线与 R10 使用各自初始化的空数据库，基线确认没有 monthly schema。最终 2,400 对 reserve/release 操作以并发 16、固定单钱包、先后及交错轮次执行，全部无遗留预扣、pending 或 charge。每条 reserve 的 driver execute 为 6，每条 release 为 8，两个版本一致；数据库内部 trigger SQL 和隐式事务命令不计入这个 driver 指标

本样本中，准入 SQL 调用中位额外约 0.10 至 0.23 ms，P95 额外约 0.11 至 0.37 ms；包含单钱包排队的整个 reserve 中位增加约 0.46 至 2.31 ms，P95 差值为 -1.94 至 +3.52 ms。内部索引检查和独立保护增加工作，不能写成零开销

受约束对照为旧固定窗口与完整月窗的相同额度核算路径，日历形态不同。第一次可能受 provision 干扰的结果只保留 exploratory；最终样本在原生业务暂停后记录 UTC 时间范围。共享主机仍有空闲后台和 UI 活动，预热样本有限；没有 HTTP、SSE、上游、Redis、原生鉴权或实际终态流量，不能据此认证 20,000 RPM

## 本地启用、回滚与剩余范围

主网关启用 monthly 开关并显式重启两个 worker，原生审计保持启用，托管密钥仍关闭且未配置真实 Vault；没有给真实账号创建月度计划。18 张财务表、3 张原生身份表及 2 张原生审计表共 23 张表，在启用及最终 UI 刷新前后 count/hash 一致。三张新月度表均为零行，1,062 个绑定文件的宿主机与容器 SHA256 一致，其中 UI 911 个

readiness、liveliness、官网、个人钱包和管理静态页面 200；未认证私有接口 401。已认证本人计划为空且 private/no-store，QA 辅助路由在主网关不存在。外部审计仍暂停、没有真实目标；本批没有新增连接池、线程池或逐请求外部 RPC
