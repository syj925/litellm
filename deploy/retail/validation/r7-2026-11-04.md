## 本轮交付

组织消费摘要与请求明细之间新增固定 CSV 任务入口。它使用已成功应用的组织和时间窗，不读取尚未应用的日期草稿，也不拼接当前页数据。创建后物化完整接纳集合、当时的五种状态、金额、名称与版本，后台只读这份固定投影生成文件

同键重试保持同一任务，相同键更换窗口为 409；成功后需明确开始新快照才再次创建。列表、详情和认证下载仅对当前可写全站管理员开放，且严格绑定同一创建者与 URL 组织。每次 Range 同样重验，组织停用和账号撤权后不能新下载。已合法下载的字节无法远程撤回

实时结果仍可随晚到结算变化，旧任务不重新取账本。待结算、未知、冲突保留当时状态，金额为空；实际零金额与未确认费用分别处理。使用、开关和回滚见 [固定组织消费 CSV](../organization-reports.md)

## 原生双 worker 与重启恢复

隔离 PostgreSQL 只克隆原生结构，零源账号或源账本。模型使用本地固定响应，启用真实零售预扣和结算，无外部模型费用或真实接收端

先验证两把 Key、两个资源池和两个 worker 的显式组织归属。随后在 A 中保留一个预扣未结算，创建含十条请求的固定任务。该任务九条 settled、一条 pending，费用 $0.0204；之后该请求真实存储层结算 $0.02，旧 CSV 的 pending 金额仍为空。另建任务变为十条 settled、$0.0404，证明新旧快照分别使用各自创建时的结果

完整下载为私有 200，Range 返回准确的 206 子串，无效范围为私有 416。相同键重放 ID 与汇总相同，改条件为 409；其他创建者或其他 URL 组织为 404，普通账号和组织管理员被拒绝，停用组织后列表与下载为 404。恢复并改名后旧任务仍保持原名称和字节

用隔离数据库中的合成租约占满两个报告槽时，另外十六个模型 HTTP 请求全部 200。另一个尚未生成的固定任务在停止代理后留下过期 processing 租约，重启两个 worker 后成功接手，仍导出最初的十条请求，字节与相同固定集合一致，未混入后来十六条请求。这是有限本地功能样本，不是压力或尾延迟认证

首次探测工具错误保留了 Docker 重启前的临时端口，并把已完成任务强行回退成 processing，造成不代表真实未完成恢复的探测。已修正为重新读取端口、使用尚无完成事件的未完成任务，再完整重跑通过；没有为迁就探测修改业务实现

同一管理员缓存会话先成功读写，再在隔离原生数据库降级为 internal_user 或 proxy_admin_viewer。读取、原幂等键创建重放和下载都立即为 private/no-store 的 403，恢复后可读。生成中的撤权场景由 API/数据库回归覆盖：允许完成私有字节生成不等于允许读取，状态和下载仍逐次现态鉴权

## 隔离、启用与剩余范围

组织任务独立建表，账号报表的表结构、取数和输出保持原含义；两类任务共享已有报告池、线程池和全局槽，没有新增推理或终态连接。预扣、结算、释放、账单和预算核算 AST 与基线相同，无新逐请求 DB/RPC 或流式分块操作

本地重启两个 worker 后，十一类既有钱包、价格、账本、预扣、额度、组织、归属与账号报表记录的指纹保持开工前值；主网关新组织报表 jobs 和 rows 均为零。未替真实账号建任务，审计外投递仍暂停且无真实目标

旧程序不会识别新组织队列；混用版本时旧账号 worker 不计组织租约，不能承诺合并上限。先全量更新报告 worker 再开放入口；回滚先关闭组织入口、停止新版 worker 并释放租约，保留新表，待恢复新版再继续未过期任务。关闭入口不改变钱包财务事实

SSO、SCIM、外部密钥、托管异步计费等仍依赖后续协议与目标配置；原生跨库审计、标签/优先级额度、委派财务、共享钱包和生产容量也未由本轮自动完成。实施清单保留实际状态，不把文档或本地固定上游验证当作生产上线
