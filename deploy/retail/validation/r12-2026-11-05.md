## 结果

固定签发方的短期 access JWT 可通过 `rt-jwt.` 适配入口映射到已有普通模型 Key。模型权限、资源池、预算、限流和钱包继续按这个 Key 处理；外部声明中的管理员角色不会提权，陈旧的本地管理员缓存也不能造成免计费。普通 Key 不增加本批数据库读取或身份提供方 RPC。

共 **2374 个去重定向用例**通过：后端单测 2201、真实 PostgreSQL 106、协议 HTTP/Redis 17、前端 50。组合回归包括已有密码登录、OIDC、Key 管理、MCP/BYOK 和原生认证，不将重复的开发期测试累计进总数。详细文件清单见 [机器记录](r12-2026-11-05.json)。

## 真实双 worker 业务验证

隔离原生 Prisma schema、实际钱包与协调 Redis、本地签名服务和固定模型上游验证了：

- 两个不同 JWT 共享同一绑定 Key 的账本身份，另一个账号扣自己的钱包；外部 role 被忽略。
- 两个 worker 均预置陈旧管理员缓存后，JWT 请求仍按当前普通账号扣费。
- SSE、Messages、Responses 完成结算；结束后无悬挂预扣。
- 公钥仍有效时关闭 JWKS 服务，热 JWT 与普通 Key 继续正常工作，期间无额外 JWKS 获取。
- 错误 token 用途/声明、未绑定身份、混合凭据、禁用回调及非模型路由在上游与钱包预扣前拒绝。
- 不允许的模型同样在转发前拒绝；普通 Key 带禁用回调 header 仍执行必要计费。
- 新配置 revision 使新 worker 与陈旧代际 worker 都拒绝旧 JWT；受控更新后新 JWT 恢复。
- 删除绑定 Key 后，仍未过期的 JWT 不能通过缓存继续调用。
- 临时 block/unblock 可恢复仍有效 JWT，这是普通 Key 暂停语义；永久撤销需要新 revision，不套用 R11 控制台会话的永久证明语义。
- 上游、stdout/stderr 和四类诊断表未出现原始 JWT、wrapper、JWT 摘要、subject、jti 或额外私有声明；账本保留原生 Key hash 作为正常计费身份。

原生事务验证还覆盖绑定配置/审计同事务、队列满回滚、revision 不复用、跨代际冲突和三动作/五动作旧审计约束升级为六动作，保留原行及设置。真实生成的 Prisma client 初始化、配置与 fresh 读取另行通过。

使用方法、签发方合同与回滚见 [API access JWT](../api-access-jwt.md)。首版要求固定 issuer、明确已有普通 Key 绑定、自定义 `gateway_revision` 及网关传输前缀；不代表已实现通用 OAuth2 签发/refresh/introspection、多 issuer、SCIM 或 SAML，也不代表 20,000 RPM 容量认证。每次 JWT 请求有新的原生 writer 权限读取；普通 Key 的额外读取为零。
