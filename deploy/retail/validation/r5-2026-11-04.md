## 功能与范围

可写全站 Proxy Admin 在 Operation Audit 打开 [Audit delivery](http://127.0.0.1:4000/ui/audit-delivery/)，查看队列、筛选状态、暂停和恢复、重试符合条件的失败项，以及确认后丢弃未完成或失败任务。普通账号、组织委派角色和只读管理员不能访问

外发只含自有管理事件的元数据，不含操作者、业务对象或组织标识、变更值、金额、提示词、凭据、原始诊断或回执。目标只由运维配置，前端和接口不接受任意 URL。详细配置、签名和限制见 [审计外投递说明](../audit-delivery.md)

这是 `CTRL-04` 的有限实现，不代表全部推理日志目标、原生回调、SMTP、阈值通知和品牌模板已完成，原有商业许可判断保持不变

## 原生双 worker 和固定接收器

隔离数据库只复制结构，没有源账号、真实账本或供应商凭据。启用真实零售计费，模型使用本地固定响应；另启一个仅在本机隔离网络内的接收器，不调用外部模型或真实通知服务

503 接收故障期间模型请求仍为 200，一次转发样本为 24.574 ms；慢响应、超时期间也成功返回模型响应。该数值只是一条本地请求，不是容量或尾延迟认证。接收器独立核对 Standard Webhooks 签名和元数据白名单，同一任务重试保持稳定投递 ID

302 没有被跟随，任务进入受控失败，人工重试后成功。200 响应声明巨大正文但未发送完时，投递先完成，证明没有等待或缓存完整响应体。429 的巨大 Retry-After 没有导致无界暂停。慢接收器、版本冲突和暂停后的丢弃按预期处理

复核发现 HTTP 客户端可能保留并回送接收端 Cookie，修复后通过两个真实发送验证不会回送，接收方仍能正确验签。成功、连接异常及取消清理 Cookie 的路径由发送层回归覆盖

同一管理员缓存会话先成功读写，再仅在测试数据库修改为普通账号或只读管理员；读请求和相同幂等键的写入重放分别被 401、403 拒绝，响应为 private/no-store，恢复后可读。普通用户为 401，未知任务为 404，未知输入为不回显原值的 422

## 本地、性能与故障边界

本地两个 worker 与专用协调 Redis 健康。管理状态和空队列为私有 200；未认证为私有 401；没有目标时启用被 422 拒绝。当前无真实接收端、无签名密钥、没有外发任务。余额、价格、账本、预扣和模型额度原记录指纹不变

生产预留、结算、释放方法的 AST 以及预算核算源码与上一版本相同，没有在推理请求路径增加查询或网络调用。外投递使用独立、最多两条连接的池，全 worker 合计两条有效租约，HTTP 期间不持有数据库连接。全部本轮隔离容器、数据库和网络均已清理

10,000 项上限达到时，新增外投递会跳过并累计缺口，本地审计和领域事务仍可提交，不承诺外部镜像无损。可能重复投递，接收方需按 ID 幂等；五次尝试、过期和人工丢弃均可能结束任务，不能把持久队列理解为必达保证

七天仅是有效配置且 worker 运行时的清理资格，缺失配置、关闭功能或存储故障会延期，压力可提前清理，硬数量上限仍有效。暂停不能撤回已发送字节。配置变化不得将旧积压静默投向新目标；关闭功能开关也不清空已持久的启用设置，要停止新增意图应先在管理页暂停
