## 交付与权限

全站可写管理员在 Organizations 的 Members 中对当前启用的组织 admin 成员明确批准 View only 或 View and export。成员关系本身不给财务权限，授权覆盖该组织已有且有接纳归属证据的历史请求。授权弹窗展示这一历史范围，不按当前成员关系补造旧归属

独立门户 `/ui/organization-finance/` 只读取安全汇总与明细。live 和 CSV 都不返回原始账号或请求 ID、供应商、成本利润、Key、价格快照或内部错误码。内部授权与创建者引用只用于服务器鉴权，公开页面不接收管理员报表 DTO

授权修改、撤销重授、成员版本变化、组织停用再启用均不会恢复旧授权代际的文件或原操作键。组织改名、其他成员变化不误伤有效授权。列表、详情、下载和每次 Range 都检查当前原生账号、凭据、组织资格及完整授权代际；已经下载的本地副本无法远程收回

原生 `customer` 原先在前端显示 Unknown Role，现映射到已有最小 App User 会话。它仍无内部用户或管理员权限，财务能力继续取决于显式 grant。原生 viewer、`org_admin` 和 `team` 不能生效，也不为接入本模块扩展原生商业角色路由

使用、默认关闭的模块开关、全 worker 升级顺序和保留结构的回滚见 [显式委派组织财务](../delegated-finance.md)

## 原生双 worker

隔离 PostgreSQL 仅克隆原生表结构，未复制源账号或账本。两个原生 worker、独立 Redis 和本地固定模型响应运行真实零售预扣及结算，没有外部模型费用或真实审计接收端

完整原生流程先重验显式组织归属、跨 Key/池/worker、不归属旧请求、晚到结算，以及管理员固定任务的十条集合与重启接手。占用两个报表生成槽时，十六个有限模型请求全部 200；这项有限功能样本不代表吞吐或尾延迟认证

R8 未授权 scopes 为空、View only 的导出被拒、精确组织 IDs 批量过滤仅返回已授权组织。首次委派 CSV 为 26 条安全记录，列固定为 sequence、model、UTC/北京时间、state、settled_nanos、settled_usd。完整下载 200，Range 为准确的 206 子串，管理员任务 ID 不能进入委派下载路径，委派任务也不能进入管理员路径

撤权后重授旧任务 404、旧创建键 409。成员停用再启用、组织停用再启用均须新批准；改名或增加另一个成员保持当前授权。只读角色和原生凭据阻断对缓存会话立即拒绝，凭据阻断在两个 worker 均生效。仅允许推理的受限 Key 无法调用财务路径

最终源码重启后再次验证当前文件、Range 和旧授权拒绝。同一账号临时成为全站管理员创建管理员文件，再降级为普通门户账号：旧管理员路径拒绝，委派路径同样 404，合法的当前委派读取仍可用。原生角色变为 org_admin 或 team 后，缓存读取被原生路由拒绝；管理员对这些目标再次给权 404 且 grant 版本不变

对隔离 grant 表施加有限锁等待，财务接口 503 且不回显表名，同期模型转发 200。授权读取仅在管理路径进行，不给模型请求增加 DB/RPC
