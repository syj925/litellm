# R13 SCIM Users 本地验收

2026-11-05；源码基线 `99be60d72ddbd04bcd28132579d355b71484311f`，本批实现 `94294b2eff8db7418cb63b55f4f3aefca12197e5`。状态 `validated_scoped_locally`：源码和 UI 已合入本地 `retail_portal` 并更新两个 worker；SCIM、OIDC、API JWT、托管密钥仍关闭。没有接真实企业目录、绑定真实客户、访问付费模型或改动生产。

## 已实现

独立 `/retail/scim/v2` 接收固定来源的 Users 创建、查询、PATCH、PUT、停用、恢复和软删除。只创建全新普通 customer，不按邮箱接管既有账号，不自动发 Key、开钱包、充值或授予模型/组织权限。目录身份、配置代际、凭据证明和四类审计事件落在原生 writer，同事务提交；满审计队列或写入失败整体回滚。

停用后普通 Key、控制台会话和映射 API JWT 在两个 worker 上均被拒绝；恢复需要新凭据，旧 hash 墓碑不能通过轮换、删除再建或换归属复活。关闭目录接收开关和移除配置后，在受支持的原生认证模式下仍保留身份检查。已经转发的请求继续完成和结算，普通非受管 Key 不增加本批数据库读取或外部身份 RPC。

本批还修复了 Key 轮换与目录停用的锁顺序：统一先处理资源、再写审计。实际业务事务在受控审计行锁下并行，修复后两项都返回 200；只恢复旧顺序时，`pg_blocking_pids` 观察到双向等待，停用返回 503。该反向验证没有改动共享源码或真实业务数据。

## 实际双 worker 业务链路

隔离的原生 Prisma schema、钱包、协调 Redis、本地签名服务与固定模型上游完成九组业务验证，未复制现有客户行：

- 新建只增加全新 customer，Key、钱包和账本不增加；重复、提权输入与既有身份接管被拒绝。
- discovery、大小写无关等值查询、count=0、GET 完整对象回传 PUT、原子 PATCH 与过期 ETag 符合限定协议。
- 受管普通 Key、SSE、真实原生 OIDC 会话证明及映射 API JWT 可用；两个 worker 的陈旧管理员缓存都不能跳过扣费。
- 停用后 Key、会话和 JWT 拒绝，新发行也受阻；恢复不会复活旧凭据，新发行可恢复。
- 有效 Key 轮换只接受当前确切 hash，旧明文无 grace；原生 Key 删除后证明仍保留。
- 四个 Key 创建请求与停用竞争，恢复后没有可用旧凭据；停用时已经接纳的延迟 SSE 正常完成并结算，无悬挂预扣。
- 同次 PATCH 先 false 再 true 仍撤销旧凭据；删除后重新建档得到新原生账号，旧钱包及历史留在旧账号。
- 两个 worker 移除 SCIM 开关和配置路径后，既有受管身份保护仍执行。
- 目录 bearer、姓名/externalId、原始 Key/会话/JWT 和私有声明未进入上游、stdout/stderr 与四类诊断表；原生 UID/hash 仍作为内部授权和计费身份。

真实生成的 Prisma client 另行验证初始化幂等、新 customer 无目录个人字段或钱包、Key 触发器、有效轮换和恢复后旧 Key 禁止轮换。数据库回归覆盖旧三/五/六动作审计约束升级到十动作，保留旧事件和设置。
