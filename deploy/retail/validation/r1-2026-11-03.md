## 真实双 worker 与故障验证

使用隔离 PostgreSQL、专用测试 Redis 和两个真实原生 worker，只复制数据库结构，未复制现有用户或账务行

- 轮换返回 200；旧 Key 在两个进程均为 401，新 Key 均为 200
- 设置 4 RPM 后，16 个并发本地模拟请求分布在两个进程，总计 4 个 200、12 个 429
- Redis 停止后，两个进程在 0.637 秒内均拒绝新的凭据请求；钱包、推理、轮换和详细诊断为 503
- 故障期间 readiness 为 503，liveness 与静态公共主页为 200
- 在测试 writer 中撤销预热 Key 后恢复 Redis，有效 Key 两边均为 200，已撤销 Key 两边均为 401
- 测试使用本地 mock_response，零售计费关闭，没有外部模型调用；隔离容器及数据库已清理并核实

这些结果验证共享限流和故障边界，不是 20,000 RPM 的吞吐或生产 SLA 认证。保护正常探测周期最多一秒，调度停滞时健康快照超过两秒则关闭新凭据请求；已开始的请求和流不追溯中断
