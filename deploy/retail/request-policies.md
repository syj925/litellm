# 自有请求策略与保存提示词

R15 为普通原生账号、Virtual Key 和精确公开模型提供独立请求约束，包含管理员页面、保存提示词及版本化绑定。这是 `CTRL-03` 的首批限定实现，不是完整的商业 Policies、Guardrails 或 Team/Organization/Project 继承体系，也不修改原生商业字段和许可检查。

默认关闭。当前实现、隔离验证、主本地启用及生产部署分别记录，最终事实以 [R15 验证记录](validation/r15-2026-11-05.md) 为准；本批不承诺生产容量或 20,000 RPM。

## 启用与关闭

服务端需要启用以下现有基础能力，并配置正常的原生认证、writer 数据库、实际 RetailBilling 回调及健康的必需协调 Redis：

```yaml
RETAIL_OPERATION_AUDIT_ENABLED: "true"
RETAIL_NATIVE_AUDIT_ENABLED: "true"
RETAIL_BILLING_ENABLED: "true"
RETAIL_REQUIRE_COORDINATION_REDIS: "true"
RETAIL_REQUEST_POLICIES_ENABLED: "true"
```

需要非空主密钥及兼容的原生认证配置；不能用匿名开发模式或自定义认证绕开当前身份校验。自有 API access JWT 仍先映射到原生 Key，并继续受到该 Key、账号及公开模型的策略约束。开启开关不等于放开原生商业 JWT/OAuth、Policies 或其他付费字段。

所有 worker 必须运行兼容版本并采用一致配置。关闭 `RETAIL_REQUEST_POLICIES_ENABLED` 会明确停止本模块的业务约束，恢复旧请求行为；数据库中的策略和绑定不会因此删除。重新开启会重新读取当前有效记录。它不是“关闭管理入口但继续执行旧策略”的撤销方案；不能把混用开关或回滚到旧二进制称为保持策略强制。

开启期间，依赖不可用会拒绝请求，不使用旧允许结果。模块未就绪或数据库/协调条件异常通常返回通用 `503`，不继续发送到上游。

## 页面怎么用

可写网关管理员在 Access Control 下进入 **Request Policies**，地址为 `/ui/request-policies/`。普通客户、组织管理员及只读管理员不能读取或修改这些私有管理记录，页面也不会为它们发起私有列表或提示词请求。

页面分为三个页签：

| 页签     | 作用                                                       | 常用操作                                              |
| -------- | ---------------------------------------------------------- | ----------------------------------------------------- |
| Policies | 定义允许的接口、输出上限和固定参数，可选引用一份保存提示词 | 创建、编辑、暂停、删除                                |
| Prompts  | 维护供策略引用的提示词                                     | 创建；主动点 Edit 后读取正文；修改、暂停、删除        |
| Bindings | 把一条策略应用到一个账号、Key 或公开模型                   | 搜索目标、选择策略、开启或关闭 Apply policy、删除绑定 |

通常先创建可选的 Prompt，再创建 Policy，最后创建 Binding。目标由服务器分页搜索，只返回安全显示名称及 opaque UUID；不需要输入或展示原生 Key hash、凭据或原生账号标识。模型目标使用本站配置的精确公开模型名，不按供应商部署 ID 或通配符授权。

每个目标最多保留一条未删除绑定。编辑绑定可以更换策略或修改 Apply policy，不能把现有绑定改成另一个目标。需要换目标时，先删除旧绑定，再创建新绑定。

保存会检查当前版本。遇到 `409`，关闭编辑器并刷新后重新检查内容，不自动覆盖或重试。重复点击保存会被禁用；明确重试相同的未确定写入会沿用幂等键。提示词正文仅保存在当前编辑器的临时状态中，取消、离开页面或失去管理员权限时清空，不写入浏览器持久存储或共享查询缓存。

## 暂停和解除的区别

| 操作                         | 对后续匹配请求的影响                               |
| ---------------------------- | -------------------------------------------------- |
| Policy enabled 关闭          | 仍在应用的绑定会使请求被拒绝，不会跳过该策略       |
| Prompt enabled 关闭          | 引用了该 Prompt 的有效策略会使请求被拒绝           |
| Binding 的 Apply policy 关闭 | 停止应用这一条绑定；其他账号、Key 或模型约束仍生效 |
| 删除 Binding                 | 停止应用这一条绑定                                 |
| 关闭整个服务端功能开关       | 停止本模块的全部策略强制，恢复旧行为               |

删除策略前先停用或删除仍在应用的绑定；删除提示词前先移除所有未删除策略对它的引用。仍有不允许的引用时返回 `409`。暂停策略后再恢复，会让仍在应用的绑定重新参与下一次请求校验。

## 约束怎么合并

一个请求最多组合精确公开模型、账号、当前 Key 三条策略，顺序为模型、账号、Key；它们不能扩大原生模型权限、角色、RPM/TPM、预算、钱包余额或其他独立授权。

| 字段                | 范围及行为                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `allowed_routes`    | `chat.completions`、`responses`、`messages`；`null` 表示没有本字段限制，空数组表示拒绝全部。多条策略取交集，交集为空则拒绝 |
| `max_output_tokens` | 整数 1–1,000,000；多条策略取最小上限，客户端传入更小的值仍采用更小值；未填表示本策略不限定                                 |
| `temperature`       | 固定数值 0–2；多条策略的非空固定值必须一致。Messages 路径不支持大于 1 的固定值，遇到时拒绝                                 |
| `top_p`             | 固定数值 0–1；非空固定值必须一致                                                                                           |
| `seed`              | 整数 −9,007,199,254,740,991 至 9,007,199,254,740,991；当前只支持 Chat，其他接口遇到固定 seed 时拒绝                        |
| `prompt_id`         | 可选保存提示词引用；多条策略的提示词按模型、账号、Key 顺序组合，合计最多 16,384 UTF-8 字节                                 |

表单中的空参数保存为 `null`，显式的 `0` 会保留。固定参数会在发给上游前设置为策略值；策略间存在不同的固定值时拒绝，不按最后一条静默覆盖。DTO 中未知字段、无效数值及不支持的输入会被拒绝。

本批仅支持 Chat Completions、Responses 和 Anthropic Messages 三类 HTTP 推理接口，以及它们的流式响应。输出上限分别转换为这些协议支持的输出字段；混合多个输出上限别名或使用错误协议字段会被拒绝。

在应用策略的 Responses 请求中，策略输出上限低于 16 返回 `403`；客户端显式请求的输出数量低于 16 返回 `400`，不会为了适配器的最小值静默抬高上限。策略字段的配置范围仍为 1–1,000,000，具体协议的边界在执行该接口时检查。

当策略包含保存提示词时，Chat 使用服务端 system 消息，Responses 使用 instructions，Messages 使用 system 字段。客户端同时传入 system/developer 指令、instructions、会话续接引用等会被保守拒绝，避免悄悄覆盖或混合服务器规则。保存提示词是真实发给模型的内容，可能增加上游输入用量；仍按原计费链路结算。

## 请求链路与不支持的路径

功能关闭时，本模块不新增每请求权威查询。功能开启后，本模块在每次请求接纳阶段执行一次有界 writer 查询，同一查询读取当前原生身份和匹配策略，不使用策略允许结果缓存；原生认证、额度及计费本身的查询仍各自存在。

接纳结果在同一次请求中用于参数准备及每次最终部署发送前的校验，检查公开模型、实际部署和固定参数没有被回调、重试或后备路径改成另一套。后续新请求重新读取当前权威，不依赖各 worker 的旧策略缓存。已接纳的流式请求使用本次快照，不承诺策略修改会收回已经发出的字节或逐帧重新计费。

开启后，客户端的上游地址、Key、provider、部署选择、fallback、路由配置、extra_body/extra_headers 等覆盖入口会被拒绝；不能用客户端路由覆盖绕开服务器选择。未知 raw/pass-through HTTP 推理路径采取保守拒绝。WebSocket（包括 realtime）以关闭码 `1008` 拒绝；这批没有对 WebSocket、Batch、后台任务、任意透传协议或新增推理协议提供策略执行支持。关闭本模块后恢复此前的这些路径行为，不代表它们已经具备同等策略保证。

管理读取和写入均重新验证当前原生 proxy_admin 身份；自定义认证不能冒充管理员。只读管理员和普通客户返回拒绝。管理变更、版本、幂等回执与原生审计在同一事务内提交；九类 prompt/policy/binding 创建、修改、删除动作出现在 Operation Audit，审计事件不保存提示词正文或凭据。

## 容量和故障边界

首版使用固定容量，删除保留墓碑，不自动释放这些累计预算：

| 记录类型                 | 上限                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| 保存提示词               | 1,000 条；单条正文最多 8,000 UTF-8 字节，中文等多字节字符按字节计 |
| 策略                     | 1,000 条                                                          |
| 目标映射、绑定、幂等回执 | 各 10,000 条                                                      |
| 单次管理列表             | 最多 100 条，offset 0–10,000；页面使用每页 25 条                  |

服务进程对本模块的权威工作使用四个并发槽，运行期策略查询最长 2 秒；这不等于全站只能承受四条流式连接，槽只覆盖本模块的数据库工作。管理事务也有有界超时与数据库锁/语句超时。容量耗尽或权威不可用时拒绝，不静默跳过约束。首版没有自动清理幂等回执、墓碑扩容或在线管理容量配置；上线前需评估变更频率和目标规模，不能靠手删审计、回执或计数绕过一致性约束。

## 提示词隐私与剩余范围

提示词列表以及写入响应只包含元数据，只有管理员单条读取才返回正文。受保护推理请求对网关诊断、日志和回调正文采用省略保护，错误向普通调用者返回通用说明。当前管理员、数据库运维方和实际模型上游仍可能接触这些内容。

模型可能主动复述收到的指令；本模块不保证模型输出永远不包含指令，也不构成 secret 保险箱。不要把 API Key、数据库密码、客户隐私或必须对上游保密的内容放进保存提示词。

尚未替代 Team/Organization/Project 的作用域与继承、通用商业 Guardrails、任意路由的 public/admin-only 配置、原生高级元数据协议、内容审核供应商插件或完整 Prompt 产品。真实上游/目录产品互通、生产部署和大规模容量需另行验收，不能把三个 HTTP 协议的本地首版写成 `CTRL-03` 全部完成。
