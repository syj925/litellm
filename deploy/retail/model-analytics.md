# Model charts and evaluations

The catalog offers source-reported benchmark charts separately from observations of this gateway. The directory's Benchmarks button opens results for the currently filtered models. A model's Benchmarks tab shows its own reported scores. Compare models also includes token-limit charts and sourced benchmark comparisons

Benchmark records retain their source, metric, version, harness, dataset, setting, evaluation date and reported rank when available. The selector separates different sources and protocols. Raw index points and Elo are not percentages, missing settings limit comparability, and capability booleans never become invented scores. Empty results remain empty. Existing metadata snapshots need a Catalog data sync after upgrading to populate the new benchmark fields

## Site observations

The Performance tab supports 24 hours, 7 days and 30 days. It charts request traffic, recorded success rate, verified time to first model output and observed output speed. UTC time buckets include partial first and last buckets. Empty timing buckets stay unknown and are not connected across gaps

`GET /retail/public/model-metrics?model=<request-model>&hours=24` returns only aggregate observations attributed to currently published public resources. Models without public resources can have an empty performance view. `GET /retail/model-metrics` requires an account and includes only that account's requests to its currently authorized pool/model pairs. These payloads contain no user IDs, credentials, upstream addresses, raw errors or financial data

Final request logs determine request counts and success rate. Retry helper rows do not inflate request counts or final token usage. Unknown outcome states keep success rate unknown. Unattributed and pre-dispatch failures are excluded. Resource visibility and access changes can affect historical coverage

## First output measurement

The native `completionStartTime` can represent a role frame, stream-opening event or heartbeat. It can also contain an end-time fallback. It does not establish TTFT in this model performance view

The separate model observation callback forwards the stream unchanged and detects the first known nonempty text, reasoning or tool-argument output. It supports recognized OpenAI Chat, Responses, Anthropic and Gemini events. Audio, image and unknown event forms do not receive guessed output timestamps. Only trusted server request identity and timestamps are persisted in `retail_model_observations`; response content is not stored there

The observation is correlated with its native log by call ID, account and server start time. Historical logs without a matching verified observation have no TTFT or speed sample. A successful noncached stream must have ordered timestamps. Output speed is final output tokens divided by observed stream-delivery time after the first output, so client backpressure can affect it. It is not an isolated vendor computation benchmark

Observation writes run separately from stream delivery with bounded work and a deadline; losing a measurement does not alter the response or billing. Metric responses include sample counts. Operational retention of the observation table should follow the site's request-log retention policy; its start-time index supports time-window maintenance

The aggregate cache is bounded to 128 entries for 20 seconds, with at most two aggregate loaders per worker. Every request rechecks the current eligible deployment set before cache lookup. Queries are read-only with an eight-second database deadline and a ten-second request deadline. No probes or paid model requests are generated by opening charts
