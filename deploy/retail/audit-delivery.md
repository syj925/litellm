# 操作审计异步外投递

本模块将自有管理操作的事件元数据投递到一个由运维配置的接收端。它不复制推理请求日志，不发送请求或响应正文，也不替代本地不可修改审计和财务账本

## 管理入口

可写全站 Proxy Admin 从 Operation Audit 页打开 Audit delivery。普通账号、组织委派角色和只读管理员没有此入口，也不能调用后台接口。每次管理请求重新核验当前原生身份，缓存会话和幂等重放不能绕过撤权

页面显示启停状态、配置是否可用及匹配、待处理和失败数量、受控错误码与溢出缺口。管理员可以暂停、恢复、重试符合条件的失败任务，或暂停后确认丢弃未完成及失败任务。配置版本冲突返回 409，须刷新后核对；未知结果使用相同幂等键查询式重试，不重复执行领域操作

页面不接收或显示目标地址、签名密钥、配置指纹和投递正文。不存在让普通用户提交任意 URL 的接口

## 运维配置

| 环境项 | 行为 |
| --- | --- |
| `RETAIL_AUDIT_DELIVERY_ENABLED` | 默认 false，依赖 `RETAIL_OPERATION_AUDIT_ENABLED`，控制接口与后台 worker |
| `RETAIL_AUDIT_WEBHOOK_URL` | 运维指定的单个 HTTPS 目标，不允许用户信息、查询参数或片段 |
| `RETAIL_AUDIT_WEBHOOK_SECRET` | `whsec_` 加严格 Base64 编码的随机密钥，解码后 32 至 64 字节 |
| `RETAIL_AUDIT_WEBHOOK_ALLOW_HTTP` | 默认 false，仅在隔离开发验证中允许明文 HTTP |

新表初始化后投递设置仍为暂停。配置环境项并启动升级后的所有 worker，再由管理员显式启用。未配置或配置非法时不发请求，也不进行空闲队列轮询。当前本地只开放管理入口，没有配置真实接收端或签名密钥，没有启用外发

目标与密钥仅存在服务器环境中，部署配置和知识库只保存占位符。URL 可以指向运维批准的内部服务，因此部署者需限制该目标和网络访问；本模块不向客户提供公共 Webhook 注册能力。HTTP 不读取系统代理环境，不跟随重定向，HTTPS 验证证书

## 外发内容和签名

每条消息只含 `event_id`、`action`、`resource_type`、`result`、`version_before`、`version_after` 和 `occurred_at`。账号、操作者、资源和组织标识、变更值、金额、业务标签、凭据、源地址、原始诊断、请求正文、幂等键及管理回执均不发送。事件和投递 ID 是服务端生成的不透明标识，可与本地记录关联

当前覆盖组织、成员、自有报表、业务标签和模型额度的成功操作。投递设置、重试及丢弃操作只记录本地审计，不再向自己入队。充值、原生 Key、全部拒绝尝试、余额阈值、SMTP、品牌模板和全部请求日志不在此批范围

签名采用 [Standard Webhooks 1.0.0](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md) 的 HMAC-SHA256 格式，核对日期为 2026-11-04。`webhook-id` 使用稳定投递 UUID，`webhook-timestamp` 使用本次尝试的 Unix 秒，`webhook-signature` 为 `v1,` 加 Base64 签名。签名输入是 ID、时间戳和实际发送字节，以英文句点连接，不重新解析再序列化正文

接收端先验签和校验时间戳，再按投递 ID 幂等处理。重试保持同一 ID，但使用新的尝试时间和签名。接收端已经接受但确认落库前进程故障时可能重复投递，不承诺恰好一次或无限重试必达

## 持久性和故障

已启用时，允许的操作事件与投递意图在同一个 PostgreSQL 事务创建，不使用时间或随机 ID 的高水位游标，因此不会因事务晚提交而被扫描跳过。暂停时不产生新外投递意图，暂停期间未入队的事件及启用之前的历史记录不自动补发；此前已入队任务恢复后继续处理，本地审计始终按原规则保留

投递 ID、原事件、配置指纹、正文和创建时间由数据库约束禁止改写。每个事件与配置只建一项任务。任务通过短事务取得租约后释放连接，再进行网络请求；结果按租约所有者、随机 token 和数据库当前时间确认，旧 worker 不能覆盖新租约结果

每个 worker 使用独立、惰性打开、最多两条连接的投递池，不使用钱包、关键终态或报表连接。数据库控制全部 worker 合计最多两条有效投递租约，租期 20 秒，单次 HTTP 总期限 3 秒。响应仅查看状态并关闭，不整段读取响应体；接收端 Cookie 不回送，客户端 Cookie 状态在每次尝试后清理

2xx 确认成功；429 和 5xx、超时及连接故障有界退避重试；重定向和其他拒绝响应进入失败。每轮最多五次尝试，错误只保存受控代码。人工重试须目标匹配、任务仍在有效期且处于失败状态，保持原 ID 并重新开始尝试计数

队列与回执合计最多 10,000 项，达到上限时跳过新增外投递并持久累计溢出计数。本地审计与领域变更仍可提交，因此外部镜像可能存在明确缺口，不是无损归档。原始审计仍是权威，不以外发成功作为财务或业务成功条件

未完成任务在七天后可被维护过程标为过期，过期任务不能重试。终态历史在完成七天后具备清理资格，压力达到 8,000 项时可提前清理；每批最多处理 200 项。维护仅在功能开启、配置有效且 worker 可运行时进行，无配置、配置失效、功能关闭或数据库故障会延期，七天不是无条件自动删除的保证，数量上限仍有效

暂停阻止新任务和新的领取，不能撤回已经发出的字节。丢弃要求暂停、当前版本及明确确认，清除待处理、发送中和失败任务的租约并保留丢弃状态；已经到达接收端的消息仍可能被处理，过期发送方的回写会被拒绝

## 配置变化和关闭

任务冻结目标与密钥配置的指纹。启动或状态查询不会改写持久目标；配置不匹配的 worker 不领取原目标任务。更改 URL 或密钥时应先暂停并排空，或者明确丢弃未完成及失败任务，再启用新配置，不能静默将旧积压发往新目标

开关关闭停止接口与后台 worker，但数据库中的已启用生产设置仍会让后续事件建立有界意图。若同时要停止入队，应先在页面暂停，再关闭开关。旧意图、原始审计和溢出计数不会因关闭被清空。回退前保留表结构和不可修改约束，不能通过删除审计来清理投递状态

本批没有在推理预留、结算、释放、逐流分块或模型转发路径增加查询或 HTTP 调用。外投递的存储和故障只属于管理面，生产容量需另行验证
