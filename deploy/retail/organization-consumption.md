# 显式账号组织归属与消费概览

全站可写 Proxy Admin 可以为零售账号选择一个已批准的组织归属，并在组织页面查看该组织接纳请求的消费概览。实际扣款仍进入账号本人的零售钱包，同一账号的不同 Key、资源池和 worker 读取同一个归属配置

本批按请求接纳时保存的组织快照统计，保留账号归属、组织和成员关系的当时版本。组织共享钱包与组织消费额度仍属于后续范围；固定组织 CSV 见 [组织报表](organization-reports.md)

## 操作入口

管理员在 Customer Wallets 的账号行打开 Billing organization，先查看当前归属及其生效状态，再从该账号的有效成员组织中选择一个组织。选择 Unassigned 可明确清除归属。账号同时加入多个组织时，管理员仍需明确选择；成员关系本身不会自动生成归属

可选列表只返回启用组织及该账号的启用、已批准成员关系，支持有界搜索和分页。已保存的组织或成员关系停用后，页面保留原选择并说明失效原因，便于管理员核对和修复

管理员在 Organizations 的组织行打开 Consumption，选择时间窗后查看请求数、状态分布、已结算 USD 和请求明细。时间窗按请求接纳时间筛选，起点包含、终点不包含。未指定时间窗时，以数据库观测时间为终点向前取七天

所有时间都必须包含明确时区，服务端统一转换为 UTC。显式起止时间必须成对提交，时间窗大于零且最多 31 天；分页每页最多 100 条，offset 最多 10,000

## 归属与晚到结算

归属修改在取得账号钱包锁后检查配置版本，选择组织时重新检查组织和成员状态。一次成功修改与 `billing_organization.updated` 操作事件在同一事务中提交。修改接口要求 Idempotency-Key，相同标识及相同请求重放原成功回执，版本冲突或同标识内容冲突返回 409

首次未配置的账号返回版本 0。明确选择或清除后建立配置记录并递增版本，后续请求读取新配置。已经接纳的请求始终保留原快照，历史请求不会随当前成员关系或账号选择迁移

例如，账号归属 A 时接纳请求，随后管理员改为 B，该请求晚到的实际扣款仍统计到 A。修改之后新接纳的请求进入 B。清除选择、停用组织或停用成员关系时，之后的请求继续使用个人钱包，但不再捕获组织归属；原有请求仍可在历史组织下结算和查询

快照包含请求 ID、组织 ID、归属配置版本、组织版本、成员版本和接纳时间，数据库拒绝对已有快照的 UPDATE 或 DELETE。归属选择只影响后续请求，不能回填或改写已有历史归属

## 消费口径

响应中的 `axis` 固定为 `admission`，时间窗选择的是 `captured_at`。本次返回的 `snapshot_at` 表示数据库事务的观测时间，汇总与当前页来自同一个 repeatable-read 视图

汇总计算整个有界时间窗内的请求集合，分页只影响明细。费用通过既有请求唯一扣款操作键关联真实零售账本，使用整数纳美元求和，并以九位小数的 USD 字符串返回。账本中的有效零金额扣款显示为 `0.000000000`

请求分为 settled、released、pending、unknown 和 conflict。只有账本可核验的 settled 请求进入已结算金额；其他状态的明细金额为 null，并单独计数。未知用量、尚待结算和事实冲突不会被当作已确认的零费用。若结算状态与账本不一致，查询返回 503，页面应保留错误状态并允许重试

最多处理 10,000 条匹配请求。服务端只取有界集合及一条溢出标记，超过上限返回 422，要求缩小时间窗；不会用前 10,000 条生成看似完整的消费小计。没有请求的合法时间窗可以返回零请求与零已结算金额

## 实时视图与固定报表

消费概览是逐次刷新取得的实时视图，响应中 `live` 固定为 true。同一次响应的汇总和明细保持一致；跨页、刷新或后续查询可能看到新结算结果。已结束的接纳时间窗仍可能因晚到结算而增加已结算金额

`partial` 表示结束时间进入当前北京时间自然日，帮助识别开放窗口。它不保证较早时间窗的结算已经最终完成。待处理、未知和冲突计数仍需一并核对

实时预览本身不保存冻结集合或 CSV。需要固定结果时，从预览下方创建独立 [组织报表任务](organization-reports.md)，后台只使用创建时物化的投影；不能把实时分页接口直接当作已冻结导出

## 权限、脱敏与故障边界

所有归属读写、组织选择列表和组织消费查询仅接受全站可写 Proxy Admin，并逐次核验当前原生账号角色和凭据状态。普通用户、组织管理员和只读管理员均不能读取或修改这些管理财务数据。对历史组织的管理员查询允许组织当前处于停用状态

接口仅返回所需的账号、组织、模型、请求状态、真实客户扣款及固定版本。请求明细不返回 Key 标识、上游身份、采购成本、利润、价格规则、原始请求内容或内部错误。操作事件的变更字段只包含本次账号和组织选择；外发审计继续使用现有受限元数据封装

管理响应与错误使用 `Cache-Control: private, no-store`，校验错误移除原始输入。未知查询字段直接返回 422。503 表示结果当前无法核验，不能当作无消费、无归属或自动放开限制

管理和报表查询使用有界诊断连接，单条语句超时为三秒，归属写入锁等待最多一秒。消费查询通过组织接纳时间索引取得集合，再按请求主键与扣款唯一键查询已有事实。查询故障不会占用财务事实关键连接或在流式分块中写库

## 配置、部署与回滚

`RETAIL_ORG_FINANCE_ENABLED` 默认关闭，启用还要求 `RETAIL_ORGANIZATIONS_ENABLED` 和 `RETAIL_OPERATION_AUDIT_ENABLED` 同时开启。公开配置中的 `org_finance_enabled` 只控制本模块管理与查询入口

已经保存的有效归属继续参与请求接纳时的快照采集，关闭管理开关不会清除配置、停止这些快照或改变个人钱包扣款。需要停止某账号之后的组织归属时，应在支持本模块的版本中明确清除其选择，或者停用相应组织或成员关系

新表随基础钱包结构初始化。快照写入合入既有钱包预扣 SQL，不额外增加逐请求远程事务；结算和释放仍使用已有终态链路。所有接纳流量的 worker 应升级到支持此结构的版本后再创建归属，混用旧 worker 会产生没有组织快照的请求

回滚到不认识该结构的旧程序后，新请求不会采集组织快照；恢复新版也不能依据当前组织或成员关系回填该时段的历史事实。新表和已有快照应保留，回滚记录必须注明采集空档，并核对已保存归属的后续处理。本轮实现及隔离数据库验证未执行生产发布

## 管理接口

| 接口 | 用途 |
| --- | --- |
| `GET /retail/admin/users/{user_id}/billing-organization` | 查看当前明确归属、配置版本和生效状态 |
| `PATCH /retail/admin/users/{user_id}/billing-organization` | 提交 `organization_id`（可为 null）与 `expected_version`，要求幂等标识 |
| `GET /retail/admin/users/{user_id}/billing-organization/organizations` | 按 q、limit、offset 查询该账号可选择的组织 |
| `GET /retail/admin/organizations/{organization_id}/consumption` | 按 start、end、limit、offset 查询接纳时间集合与实时结算结果 |
