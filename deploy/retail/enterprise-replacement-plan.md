# 网关授权功能自主替代方案

状态：首批已完成本地验收，R2 业务分类与管理来源实施中

更新日期：2026-11-04

源码基线：`retail_portal`，`e3f8f7d3442134800d42edb77e1f990851e695d2`

## 目标与范围

在现有零售网关上逐步补充自有组织、委派权限、操作审计、经营报表和按需扩展能力，继续复用已有登录、资源池授权、价格快照与 PostgreSQL 钱包结算

第一批交付以组织成员管理、操作审计和按账号账本生成的经营报表为边界。组织共享钱包、跨账号代发 Key、原生企业角色兼容、异步任务计费和复杂策略引擎分别立项，不作为组织页面上线时的隐含能力

功能盘点见 [授权功能清单](enterprise-feature-inventory.md)，任务、依赖及全部盘点项归属见 [实施任务清单](enterprise-replacement-backlog.json)。首批实际入口、运行限制与使用方法见 [自有管理功能](retail-management.md)，规划、实现、验证与生产部署分别记录

## 当前可复用能力

已有的个人账号、普通 API Key、资源池及 Key 策略交集、模型动态销售价、客户折扣、预扣、终态事实与幂等结算继续保留。普通请求 Logs、常规 Usage、Redis 协调、多进程和普通 RPM/TPM 控制不能整体归为商业功能

零售 Key 轮换已有独立路径，先验证启用条件和当前服务实现。SSO 有免费人数额度；高级 Auto Router 有独立的签名功能额度。前端提示、后端许可检查和商业模块依赖分别记录，不能以隐藏提示作为替代完成标准

现有业务约束以 [访问控制](access-control.md)、[请求容量与结算](concurrency-and-settlement.md)、[请求追踪](request-tracing.md) 为准。本规划不改变客户实际扣费口径，原生 Spend 不能直接作为零售收入或客户账单

## 代码来源与模块边界

依仓库 [LICENSE](../../LICENSE) 与 [enterprise/LICENSE.md](../../enterprise/LICENSE.md) 分别核对代码来源。新功能从需求、公开接口及自有数据模型实现，复用代码时保留对应许可与声明

自有功能使用独立的 `retail` 接口、数据表和权限域。保留原有授权检查，不把自有模块伪装为原生 Enterprise，不修改 `premium_user` 或许可结果。原生许可模块的内存判断没有显著并发优化价值

复用原生 `user_id`、`team_id` 作为外部引用，不把自有组织角色写成原生 `org_admin`、Team Admin 或 Proxy Admin，也不借用原生 `organization_id` 触发未实现的预算与继承逻辑

## R0 基线与容量要求

核对实际镜像、源码覆盖层、UI 构建、worker 数、数据库连接预算以及 Redis 生效来源。仅启动 Redis 容器不等于网关已使用它；先接共享协调状态，完整模型回复缓存独立决策

在两个及以上 worker、隔离账号和本地固定上游下验证跨进程限流、路由冷却和配置失效。Redis 断连时记录真实降级行为，确定新能力是否应拒绝请求；不能静默放宽已承诺的强限额。钱包继续以 PostgreSQL 事务为权威

新增功能的对照测试保持相同硬件、进程数、请求体、流时长、上游延迟和到达率。容量目标中的 20,000 RPM 约为每秒 333.3 个新请求，不能与同时连接数混用；活跃流数量还取决于流持续时间

基线记录网关处理开销的 P50/P95/P99、转发前处理、首次上游事件、首次模型输出、终态事实持久化、吞吐、错误率、CPU、内存、连接池等待、日志和结算队列。R1 控制面功能的推理路径新增数据库查询及外部 RPC 目标为零

R1 评审时锁定数值化性能预算。初始建议在同负载下新增网关开销 P95 不超过 2 ms、P99 不超过 5 ms、可持续吞吐回退不超过 5%；这些是待验证的放行阈值，不是当前测量结果。接近测量噪声或不能区分上游时间时重新建立基线，不用平均延迟代替尾延迟

## R1B 组织和权限设计

### 权限矩阵

以下为待实现的自有角色。组织成员关系本身不授予模型调用、其他账号钱包或原生管理权限

| 操作 | Proxy Admin | 自有组织管理员 | 自有组织成员 |
| --- | --- | --- | --- |
| 创建、停用组织 | 允许 | 拒绝 | 拒绝 |
| 查询组织信息 | 全部 | 本组织 | 本组织基础信息 |
| 维护成员与自有组织角色 | 允许 | 首版仅启停已批准关联的普通成员，不能关联任意账号或提升全站角色 | 拒绝 |
| 任命或移除组织管理员 | 允许 | 首版拒绝 | 拒绝 |
| 修改全站价格、渠道、资源池、客户充值 | 保持现有权限 | 拒绝 | 拒绝 |
| 查看其他成员 Key、日志或消费 | 现有管理权限 | 首版仅成员目录及组织管理事件；跨账号用量另需显式授权 | 拒绝 |
| 代其他账号创建或轮换 Key | 保持现有权限 | 后续独立任务，首版拒绝 | 拒绝 |
| 查看供应商地址、成本、凭据、内部错误 | 保持现有管理权限 | 拒绝 | 拒绝 |

管理员只读角色是否开放新组织的只读页面需在接口评审中单列；不能因原生菜单可见而自动赋予新接口权限。无认证返回 401，本组织内缺少操作能力返回 403，无权识别的其他组织或对象返回一致的 404。列表计数、筛选、导出和详情使用同一服务端范围

成员关联首版由 Proxy Admin 确认账号资格及客户归属后显式批准，不自动向第三方发送邮件。自有组织管理员不能凭已知 user_id 拉入任意账号，也不能由关联成员获得其历史钱包或账单。成员目录不得提供跨组织账号搜索或账号存在性探测。并发修改需要版本校验，冲突返回 409；最后一名组织管理员的移除或停用在同一事务内检查，并提供全站管理员恢复路径

新管理请求、任务状态查询和下载逐次核对账号状态、持久成员关系及授权版本，或采用经验证的同等强一致机制。无法确认现态时返回可重试的不可用，不沿用过期的允许结果。这些读取只发生在控制面。成员撤销和组织停用在下一次管理请求及导出下载授权检查生效，不能仅等待浏览器刷新或本地缓存过期。跨 worker 的缓存失效需带版本并有有界退路；Redis 不可用时不能继续使用已知过期的委派权限

### 数据模型草案

首批已实现组织、成员、操作事件及报表数据表；团队关联和组织历史财务仍属于后续方案。以下设计表与当前行为的对应关系见自有管理功能说明

| 拟议表 | 主要内容 | 约束 |
| --- | --- | --- |
| `retail_organizations` | ID、名称、启停状态、版本、创建与更新时间 | 停用保留记录，ID 不复用 |
| `retail_organization_memberships` | 组织、用户引用、自有角色、状态、版本及有效时间 | 组织与用户唯一，角色取受控枚举，保留成员变化记录 |
| `retail_organization_team_links` | 组织和已有团队的关联 | 不修改原生组织字段，不隐式转移原生团队权限 |
| `retail_operation_events` | 操作者、作用域、操作、资源、版本、结果、关联 ID、发生时间、脱敏变更摘要 | 事件 ID 唯一，业务写入事件与领域变更一致 |
| `retail_report_jobs` | 调用者、组织范围、固定时间窗、币种、状态、游标、产物、过期时间 | 重试幂等，下载重新授权，产物有大小和有效期限制 |
| `retail_report_rows` | 有界物化的报表明细投影、源账本 ID、纳美元金额和快照序号 | 同一任务的明细集合固定，唯一源记录，禁止复制请求正文和供应商秘密 |

原生账号与 retail 数据库不保证处于同一个数据库。只有在实际同库且模式兼容时建立外键；其他部署用服务端引用校验和受控停用策略，不能承诺跨数据库事务原子性

R1 不增加组织资金余额、组织预扣或组织结算表。后续若做共享钱包，必须单独评审余额权威、锁顺序、幂等、退款、转移、停用和跨进程并发，不能由成员分组自动推导

## R1A 操作审计要求

区分管理操作审计、推理请求日志和财务账本。操作事件记录谁在什么范围内对什么对象做了什么、是否成功以及变更版本，不保存可用 API Key、密码、cookie、token、供应商凭据或客户原始提示词

同库且可控的业务写入与审计意图在同一数据库事务持久化。原生管理接口或跨库写入应在权威业务数据库内接入事务 outbox，再汇集到自有审计查询；不能在前端收到成功响应后才补一条事件。无法原子接入的操作单独列为未覆盖，不宣称已完成审计

事件不可持久化时，受控变更不返回成功；外部审计转储失败可由后台重试，不反向撤销已经提交的领域事务。结果未知的充值或其他不可安全重放写入只进入核对流程，不自动重放财务事务。财务事实仍使用已有关键持久化路径，不能用审计事件替代扣费证据

R1 逐类声明原子覆盖范围。充值、改价、折扣、资源授权、Key 操作和组织成员变更分别确认拦截位置；原生 Key 或其他跨库写入在持久桥接完成前保持未覆盖，不能列入已验收事件类型；不要求调用受限原生审计接口。字段摘要使用允许清单，敏感字段只记录发生变更，不记录旧值或新值。客户和自有组织管理员只获得允许的事件投影

数据库权限限制审计的更新和删除；清理策略、保留时间、导出访问和保留例外由管理员明确配置。普通应用账号不能任意修改历史事件。未引入额外不可篡改存储时不宣称具备防管理员篡改能力

## R1C 经营报表与历史归属

收入、充值、退款或预扣释放的口径取已有 retail 账本及冻结价格。原生 provider Spend、预扣余额和实际客户消费分列。金额沿用现有 `amount_nanos`、`balance_nanos` 的纳美元口径及 Decimal 换算规则，不另造精度或以浮点数重新计算账单

默认报表使用明确标注的北京时间窗口，底层规范化为 UTC，采用左闭右开区间 `[start, end)`。每个报表固定账号范围、流水类型、币种和截止时间；未结束的自然日标记为部分窗口。多币种分别汇总，未定义汇率规则前不合并金额

完整窗口导出独立于现有 Billing 的当前页导出。首版在专用报告连接的一致性事务内物化受限行数、受限时间窗所需的最小账本投影，随后分页导出固定快照。物化和生成均限制时长、并发、行数及产物大小，超限拒绝或要求拆分窗口，不占用推理与终态结算连接池。业务时间截止和最大自增 ID 都不能单独充当提交水位；在截止前开始但快照后才提交的结算，不进入该任务快照，后续任务需明确晚到记录口径。分页、重试与 worker 重启必须保持同一任务的行集合及金额一致。未知、待结算和冲突记录单列，不按零处理

历史组织归属不能由今天的成员关系追溯重写。个人账本导出可先交付；组织级财务归属需新增请求时的不可变归属快照或等价的可信有效期记录。旧数据没有证据时归入未归属，不回填猜测。按当前成员筛选的查询必须明确标为成员范围查询，不称为历史组织财务报表

导出任务只保存必要的固定筛选与范围，产物按调用者、组织和任务隔离并私有保存。通过认证下载入口逐次校验，设置 private/no-store 缓存策略；公开 URL 或可绕过撤销的长期签名直链不作为交付方式。Range、续传和重复下载也校验当前权限，后台任务在发布产物前重新校验。已经合法下载的字节无法通过后续撤权收回。查询状态和下载时重新验证当前权限；任务创建后的成员撤销、账号停用或组织停用要阻止下载。错误提示、任务计数与可猜测 ID 不泄露其他客户的数据

## 迁移与回滚

采用新增表和新增接口，默认关闭功能。`RETAIL_OPERATION_AUDIT_ENABLED`、`RETAIL_ORGANIZATIONS_ENABLED`、`RETAIL_ORGANIZATION_DELEGATION_ENABLED`、`RETAIL_REPORT_EXPORT_ENABLED` 已在首批实现，实际依赖及关闭行为见 [自有管理功能](retail-management.md)。后续批次新增开关分别验收

迁移只做有界结构调整。现有大账本不在启动迁移中批量重写。历史补录如确有需求，使用独立、有游标、可暂停和可核对的任务；保留原始数据与记录数量、金额校验结果

验证顺序为独立数据库、本地固定上游、只读影子查询、限定管理员、限定组织、逐步扩大。影子模式不建立第二套扣款权威，不双重修改钱包，也不自动修复差异。开关开启前检查数据库版本、字段兼容和后台 worker 状态

回滚关闭新组织和委派写入入口，保留审计、组织记录及导出任务状态。暂停新增导出并关闭下载后继续做范围检查；运行中的任务可停止或留待恢复。组织开关关闭时既有原生账号和按账号计费继续按原规则工作，不能把新角色退化成全站管理员或扩大原始权限

组织状态与数据升级后需要兼容旧二进制的读写范围。不能通过回滚代码撤销已经完成的充值、扣费、退款或已签发凭证；这些操作分别使用账本冲正或独立撤销流程，权限和审计记录仍然保留

| AC01 | 非成员猜测组织、成员、Key、事件或导出 ID，含列表和筛选 | 服务端一致拒绝，不暴露对象存在性、数量或内部字段 |
| AC02 | 组织管理员提交原生管理员角色、其他组织 ID、上游配置、充值或改价字段 | 拒绝越权及未批准的任意账号关联，原生角色与钱包记录不变 |
| AC03 | 跨 worker 撤销成员、停用账号或组织后继续查询、写入和下载 | 下一次管理请求或下载检查即失效，不依赖页面刷新 |
| AC04 | 两个管理员并发改同一成员或删除最后一名管理员 | 版本冲突或事务检查生效，不发生丢失更新及无恢复入口 |
| AC05 | 写入超时、事务回滚、审计存储失败和重复提交 | 无未留持久审计的成功受控变更；跨库未覆盖类型保持未验收，幂等提交不重复产生领域副作用 |
| AC06 | 在账号所属组织变化前后查询旧账单 | 原账号账本与已存在归属快照不变，无证据旧流水不猜测归属 |
| AC07 | 跨午夜、时区、分页、多类型流水、多个币种和待结算记录 | 含延迟提交和并发结算，固定快照无重复无遗漏，重试/重启行集合不变，精确汇总与账本一致 |
| AC08 | 导出任务重试、worker 重启、生成中权限撤销及产物过期 | 任务幂等，私有产物无直链绕过，状态/下载/Range逐次授权，越权和过期产物不可读 |
| AC09 | Redis 不可用或缓存失效消息丢失 | 不静默恢复已撤销委派权限，记录有界恢复和故障策略 |
| AC10 | 新功能关闭及版本回滚 | 原账号登录、Key、路由和账本行为维持既有授权，新角色无提权 |
| AC11 | 普通用户和自有组织管理员查看事件、日志、报表、错误和导出 | 供应商身份、地址、成本、凭据、堆栈和客户原始内容遵循既有投影 |
| AC12 | 同负载功能开关对照、长流、慢上游、断连与终态队列压力 | 记录尾延迟和吞吐，R1 推理路径无新增 DB/RPC，账本唯一、预扣和队列可核对 |

有逻辑的功能通过定向测试、接口验证和必要的真实浏览器检查验收。纯文档修改只检查内容、引用及清单一致性，不以未运行的业务测试声称功能可用
