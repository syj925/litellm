# 自有业务标签与管理来源

本模块为 Key、团队、自有组织和数据库管理的模型部署保存独立业务分类，入口为 `/ui/business-labels/`。标签仅用于管理分类，尚未接入请求授权、路由、用量归集或预算执行

## 使用与权限

仅当前有效的全站 Proxy Admin 可以搜索对象、读取分类或修改标签。组织管理员和普通账号不能使用此全站管理入口，也不会因标签获得任何原生权限

选择对象类型并搜索名称，打开对象后维护标签。标签使用小写 ASCII 分类名，单个长度最多 40 个字符，每个对象最多 10 个，不允许重复。适合使用 `production`、`support`、`internal` 等稳定类别；没有从请求正文或原生自由元数据自动生成标签

修改使用当前版本与幂等标识。并发修改返回 409，需要刷新并核对最新版本后重试；失败重试不能默默覆盖另一位管理员的修改。空标签集合表示清除当前分类，已有来源和操作事件继续保留

## 对象身份与历史

列表返回独立 opaque UUID，不返回 Key 明文或 token hash。内部绑定使用对象类型、原生标识、创建时点及必要的归属指纹；原生凭据标识仅保存在私有绑定字段中

Key 轮换或删除后重建时，新创建时点或原生标识取得新的引用，需要重新确认标签。同名或相同别名不作为继承依据。当前持有人或团队与绑定不一致时，旧引用不可用。缺少可信创建时间的历史 Key 不开放分类，避免猜测生命周期

当前归属指纹不是历史转移版本。如果 Key 从 A 转给 B 后再转回 A，原生标识与创建时间均未变化，原绑定可能重新匹配；本模块没有追踪全部原生归属变更。分类不作为租户权限、财务归属或预算继承依据

模型范围为 `LiteLLM_ProxyModelTable` 中的数据库管理部署，不包含仅在配置文件或公共目录中出现的模型。自有组织开关关闭时，组织目标不可通过分类入口访问

标签记录的创建人、修改人、时间与服务器来源单独保存。首次打标签的时间不是 Key 或模型的原始创建时间。原生对象来源存在时另行显示，缺失历史显示未记录，不回填猜测

## 数据与审计

标签、版本和对应成功事件在同一个 retail PostgreSQL 事务内提交，审计写入失败回滚分类修改。事件仅保存对象类型、opaque 引用、版本和标签数量，不保存标签内容或凭据

幂等重试使用私有回执，重放前仍检查当前目标生命周期。新接口和验证错误使用 `private, no-store`，不回显验证失败的原始输入

原生 writer 的对象核验与 retail 数据修改属于不同数据库事务。本模块不声明跨库原子提交；已删除目标的旧分类记录不授予任何调用或读取权限，后续读取继续核验当前对象

## 请求链路与容量

本模块仅由管理请求使用，不新增推理回调、逐请求数据库查询或外部 RPC，不改写原生商业标签、模型配置或钱包表

对象查询只读取允许的最小字段，具有分页、查询时限和并发上限。分类与审计写入使用诊断连接池，不借用财务或终态事实连接。数据库或原生授权不可用时返回脱敏 503，不复用旧的允许结果

上限是每个对象的标签数量和长度限制，不代表全局唯一标签数量恒定。当前没有按标签生成高基数监控维度，也没有请求端任意标签导入

## 配置与回滚

`RETAIL_OBJECT_METADATA_ENABLED` 默认为 `false`，同时依赖 `RETAIL_OPERATION_AUDIT_ENABLED=true`。模块开关关闭后保留记录和事件，阻止新接口使用；不影响原有 Key、模型调用及账号账本

数据库初始化仅新增表和索引，不批量重写现有原生对象、钱包或大账本。启用后重启相应 worker，页面根据 `/retail/config` 的能力标记显示可用状态

后续模型或标签预算必须另行实现原子预留、结算和释放，并进行并发及故障验证。本页可用不代表预算、策略、日志目标或企业身份等后续任务已经完成
