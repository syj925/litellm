# 自有组织、操作审计与账本报表

本批使用独立的 retail 表、接口和角色，不修改原生商业许可判断，不把自有组织角色写入原生组织或全站管理员字段

## 使用入口

| 页面 | 用途 | 首版权限 |
| --- | --- | --- |
| `/ui/organizations/` | 创建组织、关联已经批准的账号、维护成员状态 | 全站管理员创建和关联账号；组织管理员仅启停已关联的普通成员 |
| `/ui/operation-audit/` | 查询组织变更和报表任务的成功操作事件 | 全站管理员查看全部；组织管理员仅查看自己组织的管理事件 |
| `/ui/reports/` | 固定时间窗的账号账本 CSV 导出 | 本人创建和下载自己的任务；全站管理员可为明确指定的有效账号创建任务 |
| `/ui/chat/api-keys/` | 使用已有自有接口轮换 API Key | 按原生账号和 Key 的实时权限校验；只读账号不能轮换 |
| `/ui/business-labels/` | 维护 Key、团队、自有组织和数据库模型部署的独立分类及管理来源 | 仅当前有效的全站 Proxy Admin |
| Customer Wallets 中的 Model budgets | 配置账号与精确模型的固定窗口消费额度，可提前安排连续的下一期 | 全站 Proxy Admin 配置，个人 Wallet 仅显示本人的当前及未来额度 |
| Customer Wallets 中的 Billing organization、Organizations 中的 Consumption | 明确选择账号组织归属，按接纳快照查询实时已结算消费 | 仅当前可写全站 Proxy Admin；详见 [组织消费](organization-consumption.md) |
| `/ui/audit-delivery/` | 从 Operation Audit 进入，管理自有审计元数据的异步外投递 | 仅当前可写全站 Proxy Admin，普通用户和只读管理员拒绝 |

创建组织时需要填写组织名称和首位组织管理员的现有账号 ID。账号关联由全站管理员确认客户归属后完成，不发送邀请邮件，也不向组织管理员提供全站账号搜索

组织管理员在成员页面可以启用或停用已批准的普通成员，不能新增任意账号、任命其他管理员或修改全站权限。最后一名有效组织管理员不能被移除，冲突时刷新后重试

普通成员只能看到自己的有效组织基本信息。成员关系不开放其他成员的 Key、日志、钱包、历史消费、上游身份或进价。组织停用不会隐式冻结原生个人钱包或转移其资金

原生只读账号保留允许的个人读取入口，不能提交新组织变更、轮换或新报表任务，也不能发送 Chat 请求。Chat 的个人 Key 页面仍可读取

## 权限与撤销

新管理请求逐次从原生 writer 数据库读取账号角色、密码重置要求和凭据的停用、过期及路由范围，再从 retail PostgreSQL 读取当前成员关系。读取失败返回可重试的 503，不复用旧的允许结果

通过原生认证链路验证的 Master 保留全站管理能力。该分支同时要求原生保留别名、服务器认证标记、全站管理员角色、已配置 Master 且未经过自定义认证；客户端提交的同名标记会被原生模型剥离，单独伪造别名或角色不成立

组织角色与原生调用权限分别判断。对其他组织使用统一的 404，已知本组织内缺少操作能力返回 403，未认证返回 401。所有列表、计数和详情使用同一服务端作用域

管理响应与认证错误设置 `Cache-Control: private, no-store`。浏览器在重新授权失败时隐藏之前的组织、成员、审计和报表缓存，不继续显示过期数据

Redis 健康时已在隔离的两个真实 worker 中验证轮换后旧 Key 均被拒绝，新 Key 均可用。原生缓存的 Redis 故障行为和故障保护单独记录，不能仅凭连接正常的结果承诺故障时立即撤权

## 审计覆盖

组织创建、更新、成员关联及变更，与对应成功事件在同一个 retail PostgreSQL 事务中提交。报表创建、完成或最终失败也保存对应事件；审计写入失败会回滚其领域变更

事件表由触发器禁止更新和删除，查询仅投影受控字段，不返回内部幂等响应、请求摘要或任何凭据。变更摘要使用明确的标量字段白名单，不记录提示词、请求正文或供应商秘密

当前覆盖自有组织、报表和业务标签的成功操作，原生充值、价格、渠道、Key 等跨库操作没有因此自动获得事务审计。标签事件仅保存类型、引用、数量与版本，不含标签内容，且不开放给组织管理员。该页面也不是全部拒绝访问尝试的安全事件中心，不能把成功领域事件扩称为全站审计覆盖

## 报表口径

报表以 `retail_ledger` 为权威，按明确的北京时间时间窗转换为 UTC 的 `[start, end)` 区间。币种为 USD，金额使用整数纳美元保存，并输出精确十进制字符串，不经浮点数转换

充值、已结算消费和预扣释放分别汇总。释放不是退款，未决、用量未知和事实冲突的请求单独显示，不能把仍然占用的预扣解释为零费用

创建任务时在有界的 SERIALIZABLE 事务中物化账本可见行集合，并冻结汇总和未决状态。任务创建后才提交的源记录不会混入同一任务，即使它的业务时间早于结束时间。重试、分页和 worker 重启复用同一快照

包含尚未结束的北京时间自然日或未来区间的报表标记为 partial，即使结束时间已在今天的较早时刻。以今天零点为不包含端点的历史窗口不包含当前日。组织历史财务没有按今天的成员关系重算，显式归属快照与管理员实时消费概览见 [组织消费](organization-consumption.md)，固定组织 CSV、委派财务和共享钱包仍属于后续批次

CSV 只包含账本标识、时间、类型、金额、余额、请求 ID 和模型，不含自由描述、供应商成本、请求正文或凭据。文本单元格防止表格公式注入

报表任务及私有产物保存在 PostgreSQL，没有可绕过认证的公共文件地址或长效签名链接。状态、完整下载和每次 Range 下载均重新授权，账号或权限撤销后不能发起新的下载请求。已经下载到本地的字节无法远程收回

后台生成器只发布私有字节，不从 worker 发布动作授予读取权限。它不依赖原始登录凭据；所有对外状态和下载入口重新核验当前权限，因此撤权后即使任务完成也无法读取。这是对原规划“发布时再次核验”要求的具体实现边界

## 请求链路隔离

组织操作、审计和轮换锁使用有界的诊断连接池，不借用推理财务或终态事实的专用连接。管理数据库耗尽返回脱敏 503；真实 PostgreSQL 测试覆盖管理连接占满时钱包仍可预扣和结算

报表另设连接池，默认每个 worker 最多两个连接。创建快照最多两个并发槽，全局最多两个有效生成租约。CSV 校验、生成和哈希在有界后台线程执行，取消或超时不会释放仍在运行的线程槽去无限排队

组织和报表的权限读取只发生在管理请求中，没有接入推理回调。显式组织归属采集随既有预扣 SQL 一起写入，不新增应用数据库往返；消费预览使用诊断池，不占用财务或终态池。后台初始化可重试，不因为新管理模块启动失败而主动停止现有推理服务

## 开关与容量边界

| 配置 | 模块默认 | 作用 |
| --- | --- | --- |
| `RETAIL_OPERATION_AUDIT_ENABLED` | false | 审计基础，组织和报表的前置条件 |
| `RETAIL_ORGANIZATIONS_ENABLED` | false | 自有组织页面与接口 |
| `RETAIL_ORGANIZATION_DELEGATION_ENABLED` | false | 已批准组织管理员的有限成员操作 |
| `RETAIL_REPORT_EXPORT_ENABLED` | false | 账号账本导出 |
| `RETAIL_OBJECT_METADATA_ENABLED` | false | 全站管理员业务标签，依赖审计；详见 [业务标签与管理来源](business-labels.md) |
| `RETAIL_MODEL_BUDGETS_ENABLED` | false | 消费额度管理和查询入口，依赖审计；已保存窗口的执行不随此开关关闭，详见 [模型额度](model-budgets.md) |
| `RETAIL_ORG_FINANCE_ENABLED` | false | 组织归属管理及实时消费入口，依赖组织和审计；关闭入口不停止已保存有效归属的采集，详见 [组织消费](organization-consumption.md) |
| `RETAIL_AUDIT_DELIVERY_ENABLED` | false | 外投递接口与后台 worker，依赖审计；真实地址与签名密钥仅在服务器配置，详见 [审计外投递](audit-delivery.md) |
| `RETAIL_REPORT_DB_CONNECTIONS` | 2 | 每个 worker 的报表连接，允许 1 至 4 |
| `RETAIL_REPORT_MAX_ROWS` | 10000 | 单任务最多物化行数，允许 1 至 100000 |
| `RETAIL_REPORT_MAX_BYTES` | 10485760 | 单产物字节上限，最大 25 MiB |
| `RETAIL_REPORT_MAX_DAYS` | 31 | 单任务时间窗上限，最大 366 天 |
| `RETAIL_MAX_REQUEST_BYTES` | 0 | 独立请求体保护，零售本地 compose 默认为 32 MiB |
| `RETAIL_REQUIRE_COORDINATION_REDIS` | false | 零售本地 compose 启用协调故障保护，避免依赖失效后继续接受缓存授权 |

报表每账号每日最多创建 20 个任务，全局最多 100 个未完成任务，租约 60 秒、最多 5 次生成尝试。产物 24 小时过期，过期元数据保留 30 天，按有界批次清理。超出行数、时间窗或字节预算时需要缩小时间段，不静默截断成不完整账单

本地 compose 使用独立的 Coordination Redis，密码通过未跟踪的环境配置注入，不开放宿主机端口。协调 Redis 与完整模型回复缓存分开，本批没有默认开启回复缓存

严格协调保护通过后台有界探测刷新本机健康快照，请求只做本地判断。共享协调失效或健康快照超过两秒后，携带凭据的新请求返回可重试的 503，新 WebSocket 握手关闭；基本存活检查和静态公共页面继续可用，就绪检查返回 503。已经开始的请求和流不追溯中断，不能宣称即时撤权

恢复时只清理本机授权对象缓存，不清空 Redis、预算计数或钱包。严格模式当前要求 `enable_redis_auth_cache=false` 且不使用原生读副本路由，避免恢复后重新从旧的共享对象或延迟副本取得授权。细节和检测边界见 [协调故障保护](coordination-guard.md)

修改开关后重启相应 worker。关闭审计会同时关闭依赖它的组织、报表和业务标签；关闭组织不会删除个人账本报表。保留表、审计和历史钱包，回滚时不映射到原生 Enterprise 入口

请求体边界及文件上传限制见 [请求体保护](request-body-limits.md)。32 MiB 也作用于 multipart 和音频文件，实际部署应按业务选值。已有 SSE 逐帧/逐块隐私边界不等于累计流量上限，本批没有为了限制响应而整段缓冲 SSE

## 已知范围

没有实现组织共享余额、跨账号代发 Key、组织历史账本归属、SCIM、大规模 SSO、外部密钥托管、异步任务计费或高级自动路由。任务状态以 [实施清单](enterprise-replacement-backlog.json) 为准，不因本页上线把其他商业功能标为完成

组织审计页面按每页 25 个已授权组织搜索与翻页，不一次加载全表，不会根据地址栏中的任意 ID 探测其他组织。选择和查询仍以当前授权页面为范围，撤权或组织查询失败时隐藏之前的选项与事件详情

本批本地功能测试不等于 20,000 RPM 的生产容量认证。此前容量结论和生产压测要求仍以 [请求容量与结算](concurrency-and-settlement.md) 为准
